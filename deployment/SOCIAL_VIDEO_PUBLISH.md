# 桌面端平台草稿（开发版）

入口：编辑器右上角「导出」→「平台草稿」。普通成片导出行为不变。

当前仅支持 **抖音、小红书**。按用户要求移除了微信视频号的账号入口、能力声明、草稿操作、页面适配和扩展域名权限；运行时拒绝视频号请求。旧平台会话未清理，已有视频号任务仅保留本机历史数据，不展示、不恢复、不执行。下文早期三平台测试记录属于移除前的历史，不代表当前支持范围。

## 内置 GEO 运行方式（2026-09-19）

不要求用户安装 Chrome 插件、打开开发者模式或手动配对。主进程使用 `geo-social-publish.ts`，按需启动内置 GEO 客户端，自动连接只监听本机随机端口的桥接。平台页面仍在 AI-cut 的 Chromium 窗口内运行。

- `desktop/build-geo-extension.mjs` 从本机 GEO 的 `apps/wechatsync-extension-dist` 构建增强副本和 `desktop-dist/geo-embedded-runtime.js`。固定 2.0.9 核心 SHA-256，保留实际 MCP 客户端及账号适配器，不修改原项目。
- `desktop/geo-embedded-host.ts` 提供 Electron 支持的 Chrome API 兼容层。GEO 的 Cookie 查询、抖音/小红书固定账号接口、标签页、存储及视频调试接口都由受限宿主实现。远端页面不能调用这层 API。
- 继续使用原 AI-cut 的 `persist:aicut-publisher-{platform}` 持久会话，不复制外部浏览器的账号数据。
- `desktop/geo-publish-bridge.ts` 校验内部 Origin、Host 和临时随机 token，拒绝第二客户端抢占。无 HTTP 调度接口，不向网页提供凭据，断线不自动重发。
- `desktop/geo-video-adapter.ts` 增加视频上传、核对、保存草稿、取消和结果查询。GEO 原 `syncArticle` 是文章草稿路径，不能直接用于视频上传。
- `desktop/geo-social-publish.ts` 保留受信 IPC、原生文件选择/授权、文件变更检查、原生保存确认、本机任务历史。不会回退到旧发布器。
- 增强副本禁用自动跨平台账号扫描、遥测、更新检查和营销页；不向所有网页注入原文章 UI。内部连接凭据只在本次应用进程中存在。

开发构建：`npm run desktop:dev` 会构建前端、主进程和内置 GEO 文件，然后启动开发版。单独构建内置文件用 `npm run desktop:build:geo-extension`。可通过 `GEO_EXTENSION_SOURCE` 指向相同固定版本的本地插件目录。

构建中间目录 `desktop-dist/geo-publish-extension/` 不是用户安装步骤。早期外部扩展配对方案已被内置方案替代；`geo-pairing-store.ts` 不在当前运行路径中。这里只提供开发版，正式分发前仍需整理上游许可、对应源码和各目标平台构建。

## 使用流程

1. 构建后重启 AI-cut，进入「导出 → 平台草稿」。连接在后台初始化，界面不展示 GEO / 插件技术提示。
2. 点击目标平台「登录 / 查看」，使用应用内平台窗口登录；已有会话自动沿用。扫码、验证码等仍由账号本人完成。
3. 账号自动刷新，也可点击「刷新状态」。抖音增强适配器用当前平台 session 查询固定用户资料接口，验证有效用户与昵称后显示「昵称 · 已登录」和「查看账号」。401 显示未登录；网络错误、验证页、未知响应均显示「账号信息暂未获取」，不误报退出或沿用旧昵称。小红书仍用原 GEO 用户信息接口。
4. 选择有权发布的视频，填写标题与正文，点击居中的「上传并准备草稿」。全局加载层阻止重复操作，所选平台的受信页面完成 DOM 加载并显示窗口后关闭；等待窗口最多 45 秒，失败/超时也关闭并提示，不自动重传。页面打开不代表上传完成或草稿保存成功。
5. 不再展示「草稿任务」模块及历史卡片。当前上传进度、查看平台、取消及「核对并保存草稿」放在对应账号行下；结束后显示简短结果。上传完成后核对平台页面中的账号与文案，通过原生确认后仅点击唯一匹配的草稿按钮一次。
6. 仅检测到明确草稿保存成功提示才记为「已保存草稿」。缺少/歧义草稿按钮、断线或重启均停止并要求核对，不回退点击发布，不自动重试。最终发布由用户在平台自行完成。

## 安全边界与限制

- 平台窗口启用 sandbox/contextIsolation，无 preload、无 Node 权限，只允许抖音和小红书两个固定创作者 HTTPS 域名；不绕过 TLS、验证码或登录。
- 调试接口只允许访问宿主创建的窗口，限定命令，未开放远程调试端口。账号接口只允许固定的抖音/小红书用户信息 GET 请求，不跟随重定向、无任意 URL/请求体权限，凭据保留在原平台 session 内。
- 上传路径必须由原生文件选择或已授权导出目录获得；检查规范路径、大小、修改时间。渲染界面不拿到 Cookie、桥接 token 或本机绝对路径。
- 每平台同时只允许一个活跃任务，保存前持久化状态。取消本机任务不删除平台已产生的草稿。
- 主界面任务历史保存在 userData/social-publish-jobs.json，保留最近 100 条。原版任务记录保留，但不能在新引擎中续传；运行中任务重启后要求人工核对。
- 网页 DOM 改变、控件歧义、登录失效时停止并提示，不猜测点击。暂不包含批量多账号、定时发布、自动封面裁剪或无人值守发布。

内置端到端测试使用真实 Electron、实际 GEO 核心、实际 WebSocket、真实调试文件上传 API；三个平台页面全部由临时 profile 的 HTTPS 协议处理器替换为本地合成页面，阻止外网请求。验证启动自动连接、会话读取、小红书 Origin 兼容及上传→待核对→保存草稿。另验证关闭并重建宿主后以新凭据自动连接、沿用合成会话、保留历史且拒绝重复保存；不持久化窗口编号，避免重启后的窗口编号复用串到新任务。没有使用真实账号，没有上传真实文件到平台，没有公开发布内容。

实测发现及修复：

- 宿主错误跨 VM 后不满足 `instanceof Error`，导致只显示笼统失败。现保留脱敏错误与失败阶段，并补充跨 VM 回归测试。
- 页面已有可用上传控件，但初始 `did-finish-load` 等待未结束，45 秒超时会调用 stop，终止正在运行的页面。现接受受信主文档的 `dom-ready`，仍单独等待上传表单、校验域名并保留网络错误处理。事件回归证明 DOM-ready 后不会被初始超时停止。
- 上传时展示平台页，加载错误也展示窗口并保留导航错误详情，避免失败窗口一直隐藏。

前三次真实任务失败，没有提交发布。修复后的第四次任务 `2201ba30-a142-4606-b895-13cef17e59ba` 已进入 uploading，实测超过 88 秒仍未被旧的 45 秒导航超时终止；尚未确认上传完成或发布成功。电脑控制工具当前只返回抖音导航菜单、无法获取表单/截图，已请用户提供平台窗口截图辅助核对。后续必须在同一任务上检查结果，不得因状态未知直接重发。

### 后续实机排查：页面就绪判断

用户截图确认抖音账号已进入内容管理；这不是草稿保存成功凭证。控制工具仍仅暴露导航菜单，未读取到草稿箱或上传表单，因此未新建上传任务。

发现宿主 tabs.get 仍用 isLoading()（包含后台资源）判断页面状态，与 dom-ready 导航处理不一致。改为跟踪受信主文档 dom-ready，新主文档导航时重置；表单、登录、域名检查保持独立。三个离线 Electron 平台夹具故意挂起一个图片资源，确认 isLoading() 仍为 true 时上传、核对、保存草稿仍能完成；类型检查通过。此修复不等于真实平台草稿已保存，下一次实机验证需重启开发版加载新主进程。

### 抖音昵称与登录状态修复（实机已验证）

原 GEO 抖音适配器只检查 Cookie，现由增强 runtime 的 `douyin-account.mjs` 接管抖音 checkAuth，其他原适配器不变。固定资料接口与字段参考 [MultiPost 开发记录](https://multipost.app/docs/en/development/douyin-account)。不把 Cookie、用户 ID 或完整资料返回界面，只返回验证状态和昵称。没有接入第三方付费服务。

回归覆盖：正常昵称、明确退出、缺字段/旧格式/验证失败、网络/验证页、账号切换，以及 IPC 丢弃过期昵称。`verify:geo-publish-bridge`、`verify:geo-embedded`、类型检查、前端/主进程构建均通过。重启当前开发版并在「导出 → 平台草稿」实测，抖音已显示当前真实昵称与「已登录」，按钮为「查看账号」。小红书当前仍为「账号信息暂未获取」，视频号仍需手动核对；本次没有上传或发布视频。
